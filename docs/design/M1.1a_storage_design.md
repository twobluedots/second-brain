## SQLite Schema

```sql
CREATE TABLE entries (
    id            TEXT PRIMARY KEY,
    content       TEXT,
    content_type  TEXT NOT NULL,       -- "text" | "voice" | "image" | "journal"
    category      TEXT,                -- from categories table, nullable
    tags          TEXT,                -- JSON array e.g. '["journal","interstitial"]'
    file_path     TEXT,                -- disk path to audio/image, nullable
    user_id       TEXT DEFAULT 'default',
    created_at    TEXT NOT NULL,       -- ISO 8601
    modified_at   TEXT,                -- ISO 8601, set on any edit
    deleted_at    TEXT                 -- ISO 8601, soft delete
);

CREATE TABLE categories (
    name          TEXT PRIMARY KEY,
    created_at    TEXT NOT NULL
);
-- Starting list: thought, mood, task, learning, idea, memory, exercise, journal
```

## ChromaDB Setup

- **Client:** `PersistentClient(path="./chroma_data")`
- **Collection:** `entries`
- **Embedding model:** default (all-MiniLM-L6-v2) — revisit post-M3
- **Document:** searchable text (content, transcription, or OCR output)
- **Metadata:** `entry_id`, `content_type`, `created_at`
- **ID:** same as SQLite `id` — the bridge between stores
- **On delete:** remove from ChromaDB when soft-deleting in SQLite

**Rule:** ChromaDB = search index. SQLite = source of truth. No file paths, tags, or categories in ChromaDB.

## Storage Class Methods

```
WRITE                           READ (SQLite)                SEARCH (ChromaDB)
─────                           ─────────────                ────────────────
save() → both stores            get_by_id()                  search(query, n)
update() → SQLite + modified_at get_recent(limit)
delete() → soft delete both     get_by_category(cat, limit)  CATEGORIES
                                get_by_date_range(start,end) ──────────
                                get_by_type(type, limit)     get_categories()
                                get_category_counts()        add_category(name)
```

All methods return `dict` or `list[dict]`, never raw tuples. UI layer never touches SQLite or ChromaDB directly.

---

## Key Rules

| Rule | Detail |
|---|---|
| Files on disk | Audio/images stay as files. SQLite stores path only. No blobs. |
| Soft delete | `WHERE deleted_at IS NULL` on all queries. |
| Categories | Closed but growable. DB table, not config. User can add new ones deliberately. LLM and user share same list. |
| Tags | Freeform. No validation. JSON array in TEXT column. |
| User ID | `'default'` for now. TEXT type for future auth compatibility. |
